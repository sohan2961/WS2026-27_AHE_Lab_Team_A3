# Seminar paper quality checklist

## Structure and grading

- [ ] One paper with three acknowledged authors (not three disconnected papers)
- [ ] Clear research question, evidence-based conclusions, limitation discussion
- [ ] 6–8 pages in IEEE two-column format
- [ ] Minimum 15 legitimate and relevant references (not counting unverified entries)
- [ ] Introduction, related work, main analysis, discussion/evaluation, conclusion, references
- [ ] Figures captioned, legible, cited where relevant; copied figures have reuse permission
- [ ] Each teammate reviewed entire text, not only their own section
- [ ] GitHub contribution record is truthful

## Topic 4 must-have points

- [ ] Explain self-attention, prefill vs decode and KV-cache memory formula
- [ ] Distinguish capacity bottleneck, data-transfer bandwidth and compute bottleneck
- [ ] Survey FPGA datapaths, dataflow, on-chip buffers and HBM's role
- [ ] Compare latency and energy/token with GPUs **from published results**
- [ ] State GPU and FPGA hardware, model, precision, batch, prompt and decode lengths when possible
- [ ] Label hardware rated bandwidth separately from measured application bandwidth
- [ ] Distinguish post-synthesis claims from measured real-hardware results
- [ ] Discuss edge vs data-center feasibility, including model fit and context length

## Before submission

- [ ] Verify the final names, full surnames if required, affiliations, author order and contact details; no invented emails
- [ ] Open every cited paper/DOI and verify bibliographic metadata
- [ ] Compare quantitative claims directly against cited table/figure/page
- [ ] Check and fix broken URLs and uncited references
- [ ] Compile PDF and inspect all pages for overflows or broken equations
- [ ] Declare AI assistance per university policy
- [ ] Ensure no fabricated results, measurements, or citations
